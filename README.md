# Ладно

[![CI](https://github.com/Aleksandr-Litvinenko/ladno/actions/workflows/ci.yml/badge.svg)](https://github.com/Aleksandr-Litvinenko/ladno/actions/workflows/ci.yml)

«Ладно» — демо управленческого учёта: счета, склад и деньги в одном интерфейсе. Каждый документ связан с остатками, движением денег и отчётами.

Публичное демо: [ladno.product1c.ru](https://ladno.product1c.ru)

Текущая версия: **0.1.0**.

> Это демо в браузере, для реального учёта оно не подходит. Расчёты показывают управленческую логику и не заменяют бухгалтерию, проверку специалистом или резервные копии.

## Что реализовано в 0.1.0

- **Счета поставщиков:** регистрация, согласование, постановка в платёжный календарь и отметка оплаты.
- **Счета покупателям:** регистрация, согласование, контроль срока, поступление оплаты и задолженность.
- **Склад:** остатки по номенклатуре и складам, поступления и отгрузки в интерфейсе, перемещения в доменном ядре и журнал движений.
- **P&L:** управленческая оценка выручки, себестоимости, операционных расходов и результата.
- **Cash Flow:** фактические входящие и исходящие денежные потоки по видам деятельности.
- **Платёжный календарь:** фактические и ожидаемые оплаты по датам с оценкой денежного разрыва.
- **Связи между документами:** по документу видно, что он изменил на складе и в деньгах.
- **Демоданные и локальное сохранение:** состояние хранится в `localStorage` текущего браузера и сбрасывается из интерфейса.
- **Заготовка под 1С OData:** в модели есть стабильные идентификаторы и поля происхождения данных. Синхронизации с 1С и учётных данных в этой версии нет.

## Как запустить

Нужен Node.js 20 или новее. Внешних runtime-зависимостей нет.

```bash
git clone https://github.com/Aleksandr-Litvinenko/ladno.git
cd ladno
npm run serve
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173).

Проверки:

```bash
npm test
npm run validate
```

## Как устроено демо

Все данные версии 0.1.0 находятся в браузере:

1. При первом открытии загружается демонстрационный набор документов.
2. Действия в интерфейсе меняют статусы и связанные показатели.
3. Состояние сохраняется в `localStorage` только на текущем устройстве и в текущем профиле браузера.
4. Сброс возвращает исходный демонстрационный набор.

В демо нет регистрации, разграничения прав, общего многопользовательского состояния, серверной базы, фоновой синхронизации и резервных копий. Не вводите реальные платёжные реквизиты, персональные данные или коммерческую тайну.

## Подготовка к 1С OData

Версия 0.1.0 не подключается к 1С и не спрашивает логин или пароль. Совместимость заложена в модели данных и в границе адаптера:

- внешний объект можно связать с entity set и `Ref_Key` источника;
- даты представлены в машиночитаемом ISO-формате;
- суммы отделены от валюты и направления движения;
- импорт проектируется как read-only и не меняет данные 1С;
- будущий коннектор должен работать на сервере, а не в браузере.

Безопасная целевая схема: браузер → собственный API → стандартный OData-интерфейс 1С. Сервер хранит секреты, проверяет разрешённые entity sets, обрабатывает `$metadata`, пагинацию и таймауты. Подробнее — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Структура репозитория

```text
index.html                 точка входа
styles.css                 визуальная система
app.js                     пользовательские сценарии и представления
src/                       доменное ядро, хранилище и OData-адаптер
tests/                     автоматические проверки логики
scripts/serve.mjs          локальный статический сервер
scripts/validate.mjs       проверка релизной структуры и явных секретов
deploy/                    пример отдельного nginx-vhost
```

## Развёртывание

Пример vhost для Jino/VPS находится в [`deploy/nginx-ladno.product1c.ru.conf`](deploy/nginx-ladno.product1c.ru.conf). Он обслуживает только `ladno.product1c.ru` и не требует менять уже работающие сайты.

Публичный HTTPS завершается на edge Jino, поэтому origin-конфигурация слушает HTTP-порт 80 и не выполняет редирект на HTTPS.

## Ограничения версии

- данные принадлежат одному браузеру;
- отчёты показывают управленческую модель демоданных;
- интеграция с OData пока описана только контрактом, соединения нет;
- создание счёта за услугу не формирует запись P&L автоматически: в демо такие
  записи заданы отдельно;
- нет импорта файлов, API для записи, ролей и журнала безопасности;
- приложение не рассчитано на хранение реальных финансовых данных.
