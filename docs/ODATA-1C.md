# Подготовка к обмену с 1С через OData

## Граница версии 0.1.0

В первой версии Ladno реализует нормализованный контракт, тестовый импорт JSON и
выгрузку демонстрационного снимка. Прямого подключения к рабочей базе 1С в
публичном интерфейсе нет.

Это принципиальное ограничение безопасности: адрес базы, имя пользователя и
пароль нельзя помещать в клиентский JavaScript. Реальный коннектор должен работать
на сервере, а браузер — обращаться только к API Ladno.

Стандартный интерфейс OData 1С публикуется на веб-сервере и может читать и менять
данные информационной базы. Поэтому для первой интеграции Ladno планируется режим
**только чтение** с отдельным пользователем 1С и минимальными правами.

Официальные материалы:

- [документация 1С:Предприятия о стандартном OData](https://its.1c.ru/db/v8312doc/bookmark/dev/TI000000783);
- [настройка состава стандартного интерфейса OData](https://its.1c.ru/db/content/edtdoc/src/topics/t000419.html);
- [руководство администратора 1С:Предприятия](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/).

## Почему нет жёстких имён объектов

Состав метаданных и имена наборов сущностей зависят от конфигурации 1С. Ladno не
предполагает, что у любой базы обязательно существует один и тот же
`Document_*Счет*`.

Порядок подключения:

1. Сервер получает `.../odata/standard.odata/$metadata`.
2. Пользователь сопоставляет найденные наборы сущностей с доменами Ladno.
3. Коннектор читает только выбранные поля через `$select`.
4. Большие выборки загружаются страницами; ссылка следующей страницы не строится
   вручную, а берётся из ответа сервиса и проверяется на тот же origin.
5. Записи нормализуются и обновляются идемпотентно.

Типовые кандидаты, которые нужно подтвердить по реальному `$metadata`:

| Домен Ladno | Возможный набор 1С |
| --- | --- |
| Организации | `Catalog_Организации` |
| Контрагенты | `Catalog_Контрагенты` |
| Номенклатура | `Catalog_Номенклатура` |
| Склады | `Catalog_Склады` |
| Счета поставщиков | подходящий `Document_*Счет*Поставщик*` |
| Счета покупателей | подходящий `Document_*Счет*Покупател*` |
| Поступления | `Document_*Поступление*` или `Document_*Приобретение*` |
| Отгрузки | подходящий `Document_*Реализация*` |
| Остатки | подходящий `AccumulationRegister_*_Balance` |

## Нормализованная запись

```json
{
  "source": {
    "connectionId": "onec-demo",
    "entitySet": "Document_...",
    "refKey": "00000000-0000-0000-0000-000000000000",
    "dataVersion": "opaque",
    "fetchedAt": "2026-08-09T12:00:00.000Z"
  },
  "entity": "supplier_invoice",
  "record": {
    "number": "4821",
    "date": "2026-08-09",
    "posted": true,
    "organizationExternalId": "uuid",
    "counterpartyExternalId": "uuid",
    "dueDate": "2026-08-14",
    "totalMinor": 24860000,
    "vatMinor": 4143333,
    "lines": []
  }
}
```

Деньги передаются в целых копейках. Экспортированные 1С десятичные строки можно
преобразовать функцией `decimalToMinor`, которая округляет строку до копеек без
промежуточной двоичной арифметики JavaScript.

## Идемпотентность и владение полями

Уникальный внешний ключ:

```text
(connectionId, entitySet, Ref_Key)
```

- повторный импорт не создаёт дубль;
- новая `DataVersion` обновляет только поля, которыми владеет 1С;
- локальные согласования, комментарии и плановые даты не перезаписываются;
- `DeletionMark` сохраняется в envelope; политика архивирования будет применяться
  серверным коннектором, а текущий upsert ничего автоматически не удаляет;
- отсутствие универсального `ModifiedAt` компенсируется перекрывающимся окном по
  `Date` или `Period`, upsert по `Ref_Key` и сравнением версии/хеша.

## Безопасный серверный коннектор

Для следующей версии:

```text
Браузер → HTTPS API Ladno → серверный OData-адаптер → HTTPS OData 1С
```

Требования:

- отдельный пользователь 1С только для чтения;
- секреты только в серверном окружении;
- TLS с проверкой сертификата;
- allowlist адресов 1С для защиты от SSRF;
- таймауты, ограничение размера ответа и количества страниц;
- журнал запусков без паролей и персональных данных;
- повторяемый импорт без дублей;
- запись, проведение и удаление объектов 1С выключены по умолчанию.
